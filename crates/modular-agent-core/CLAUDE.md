## Overview

This is the core orchestration engine for the Modular Agent framework, implemented as a Rust workspace with two crates:

- **modular-agent-core**: Main library implementing the agent system
- **modular-agent-macros**: Procedural macros for agent declaration (`#[modular_agent]`)

## Build Commands

```bash
cargo build                                            # Build all packages
cargo test --all-features                              # Run all tests
cargo test --all-features --package modular-agent-core # Test core library only
cargo test --all-features --package modular-agent-macros # Test macros only
cargo run --example cli -- <patch.json> [-i input] [-o output] # Run CLI example
```

## Core Concepts

1. **ModularAgent** (`modular_agent.rs`): Central orchestrator managing agent lifecycle, connections, and message routing. Maintains agent instances, connection maps, and handles ModularAgentEvents.

2. **Agent Trait** (`agent.rs`): Interface for agent implementations. Agents receive messages via channels and process them asynchronously.

3. **AgentContext** (`context.rs`): Event-scoped context that tracks data flow across agents. Contains variables and frame stacks for map operations.

4. **AgentValue** (`value.rs`): Union type supporting primitives, strings, images, arrays, objects, tensors, messages, and errors. Core data type flowing through the system.

5. **AgentDefinition** (`definition.rs`): Metadata and configuration specs for agents, generated by the `#[modular_agent]` macro.
   - `reconcile_spec()` reconciles old JSON patches with current definitions: fills missing config keys with defaults, renames stale keys with `_` prefix for lazy migration, and overwrites ports/config_specs.
   - Config names starting with `_` are reserved for stale key migration — the `#[modular_agent]` macro rejects them at compile time.
   - `AgentData::new()` auto-strips `_`-prefixed keys after `AsAgent::new()` has had a chance to read them.
   - `///` doc comments on the struct are extracted as `AgentDefinition::description` (explicit `description = "..."` takes priority).

6. **Patches** (`patch.rs`, `spec.rs`): Collections of agents and their connections defined in JSON format.

## Message Flow

```
External Input → ModularAgent → Routes via connections → Agent processes → Broadcasts to connected agents
                                                                        ↓
                                                         External outputs (special handling via external_values + external_input_agents)
```

## Built-in External I/O Agents

External agents bridge external I/O with the agent network:

- **ExternalInputAgent** (`ExtIn->`): Entry point for external input. Listens to `write_external_input()` and forwards values to connected agents.
- **ExternalOutputAgent** (`->ExtOut`): Exit point for external output. Receives values from agents and emits `ModularAgentEvent::ExternalOutput`.

Local agents provide patch-scoped variables:

- **LocalInputAgent** (`LocalIn->`): Entry point for patch-scoped local input.
- **LocalOutputAgent** (`->LocalOut`): Exit point for patch-scoped local output.

## Usage Example

```rust
// 1. Initialize
let ma = ModularAgent::init()?;
ma.ready().await?;

// 2. Subscribe to output BEFORE starting (avoid race condition)
let mut rx = ma.subscribe_to_event(|event| {
    if let ModularAgentEvent::ExternalOutput(name, value) = event {
        if name == "output" { return Some(value); }
    }
    None
});

// 3. Load and start patch
let id = ma.open_patch_from_file("patch.json", None).await?;
ma.start_patch(&id).await?;

// 4. Send input / receive output
ma.write_external_input("input".into(), AgentValue::string("hello")).await?;
if let Some(value) = rx.recv().await { /* handle output */ }

// 5. Cleanup: stops running patches, waits for tasks, drains MCP connections;
//    errors with AgentError::ShutdownTimeout after the timeout.
ma.shutdown(Duration::from_secs(5)).await?;
```

`quit()` remains for tests and simple cases (synchronous, does not wait for anything).

## Feature Flags

- `file`: File handling support
- `image`: Image processing (photon-rs)
- `llm`: LLM integration with Message/ToolCall types
- `mcp`: Model Context Protocol integration
- `test-utils`: Testing utilities

Default features: `["file", "image", "llm", "mcp"]`
